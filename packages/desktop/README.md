# @ide/desktop

Electron-оболочка CodeRay: dev-окно вокруг dev-стека (`pnpm desktop`) и сборка `.app` для macOS (`pnpm desktop:dist`, см. «Сборка для macOS»).

## Запуск

```
pnpm desktop                 # проекты, открытые в прошлый раз, или стартовый экран: создать, открыть, склонировать
pnpm desktop -- /path/to/project
pnpm desktop -- .            # разработка самой IDE в IDE: hub остаётся под --watch
```

Несколько проектов живут вкладками одного окна: «+» (⌘T) открывает меню, ⌘P палитру, ⌘1–9 переходит к проекту, ⌃Tab листает по недавности, ⌘W закрывает проект. У каждого открытого проекта свой core и свой агент, они работают в фоне; когда проекту нужен ответ или он закончил, на его вкладке появляется пузырь.

`main.mjs` за один запуск:

1. генерирует случайный токен;
2. поднимает vite dev server UI и hub (`node --watch ... --hub`, токен в `IDE_CORE_TOKEN`) на свободных портах, которые выдаёт ОС (порты не фиксированы, с запущенными `dev:core`/`dev:ui` не конфликтуют). Hub запускает по одному core на каждый открытый проект (свой порт и токен у каждого), UI подключается к hub и к каждому core напрямую;
3. ждёт, пока оба порта слушают, и открывает окно на `http://localhost:<порт UI>/#token=<токен>`.

Закрытие окна (или Ctrl+C в терминале) завершает оба процесса вместе с потомками.

## Как работает рестарт

- Правка UI: vite HMR, окно не перезагружается.
- Правка core: `node --watch` перезапускает hub, он гасит свои core и поднимает открытые проекты заново (список и порядок в `~/.ide/open-projects.json`). Токен лежит в окружении родителя (электрон-процесса), поэтому после рестарта тот же. Порт hub выбран один раз за запуск и не меняется при рестартах, vite проксирует `/ws` на него (`IDE_CORE_PORT`). UI сам переподключается с backoff (`net/socket.ts`), URL и окно не меняются.

## Ограничения

- Рестарт hub останавливает агентов всех открытых проектов: процесс `claude` дочерний у своего core. Оболочка ставит `IDE_AUTO_RESUME=1`: после рестарта каждый core сам возобновляет сессию (`--resume`) сообщением «продолжай с места остановки». Отключить: убрать эту переменную в `main.mjs`.
- Меню приложения заменено: ⌘W закрывает проект, а не окно (окно закрывает ⇧⌘W).
- Токен и порт нужны только окну; открывать ссылку из лога core в обычном браузере можно, но только пока оболочка запущена.

## Сборка для macOS

```
pnpm desktop:dist                    # подписанный и нотаризованный dist/CodeRay-<версия>-arm64.dmg
pnpm desktop:dist -- --no-notarize   # только подпись, для быстрой проверки
pnpm desktop:dist -- --dir           # только dist/mac-arm64/CodeRay.app, без .dmg
```

Нужны сертификат `Developer ID Application: Evgenii Shestakov (4N9UMF2P33)` в связке ключей и профиль `notarytool` с именем `notary` (другой профиль задаёт `APPLE_KEYCHAIN_PROFILE`). При первой подписи `codesign` спрашивает доступ к ключу: «Разрешать всегда». Сборка только под arm64.

`build-app.mjs` собирает:

1. UI (`vite build`) в `Resources/ui`;
2. core одним бандлом esbuild в `Resources/core/dist/bin/main.mjs`, рядом воркер эмбеддингов и скрипты хуков. Пакеты, которые не входят в бандл (нативные аддоны, wasm-грамматики tree-sitter), копируются в `Resources/core/node_modules` из установки воркспейса, то есть ровно тех версий, что в lockfile. Бинарники onnxruntime остаются только для darwin-arm64;
3. `Resources/bin/ide-node`: запускает бинарник приложения как Node (`ELECTRON_RUN_AS_NODE=1`).

Отдельного Node в приложении нет: hub, core проектов и хуки Claude Code работают на самом Electron. Core при старте убирает `ELECTRON_RUN_AS_NODE` и `IDE_NODE` из окружения, поэтому агент, терминалы и MCP-серверы их не наследуют, а свои процессы (хуки, core проектов) запускает через `ide-node` (`packages/core/src/node-exec.ts`).

В собранном приложении `main.mjs`:

- берёт `PATH` из login shell: из Finder приходит урезанный PATH, на котором нет `claude`;
- запускает hub без vite: hub сам отдаёт UI, окно открывается на его порту;
- передаёт токен через stdin с `--exit-with-parent`: если приложение убито, даже SIGKILL, hub и core завершаются сами;
- пишет вывод core в `~/Library/Logs/CodeRay/core.log`; если core упал до старта, показывает окно с путём к логу;
- держит один экземпляр: повторный запуск фокусирует уже открытое окно.

Ограничения сборки: общий с dev-окном `~/.ide`, поэтому один проект не открыть в обоих сразу (блокировка проекта); нет иконки и автообновления.
